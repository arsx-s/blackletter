# Web research: retrieval with provenance

Mission 8 turned "search the web" from a prompt into a pipeline that fetches bytes
from approved URLs, keeps a record of exactly what it received, and binds a
synthesis to passages that reproduce from that record.

> **The line this document will not blur:** a *source* is bytes fetched from a
> URL and stored with a digest. A *claim* is a sentence someone wrote. Support is
> only ever counted from the first to the second — never the other way round, and
> never from a provider's snippet.

The code lives in `src/research/web/` — **inside** the existing research module
(`src/research/analysis`, `…/document`, `…/output`, `…/project` are the modelling
layer that was already there). The retrieval layer is additive; an architecture
guard fails the build if `src/research/types.ts` or `src/research/index.ts` (the
pre-existing modules) are replaced or emptied.

## The pipeline

| Stage | What happens | Where |
| --- | --- | --- |
| 1. Frame | question, domain, jurisdiction, period, "what is missing" | panel → `ResearchQuestion` |
| 2. Plan | deterministic, bounded query set (≤ 4) | `buildSearchPlan` in `run.ts` |
| 3. Retrieve | provider search → candidate URLs | `SEARCH_PROVIDERS` in `run.ts` |
| 4. Fetch | approved hosts only, limits enforced | `fetch.ts` |
| 5. Extract | title, byline, publisher, date, canonical URL, text | `extract.ts` |
| 6. Store | content-addressed source records + digests | `buildSourceRecord` in `analysis.ts` |
| 7. Bind | claims → reproducible passages → independent sources | `bindClaims` in `analysis.ts` |
| 8. Report | conflicts, refusals and an honest summary | `detectConflicts`, `summariseRun` |

The plan is generated by code, not by a model: the question as asked, its
distinctive terms with the declared domain, those terms with the jurisdiction and
period, and a variant biased at official publications. A run can therefore be
reproduced, and a reviewer can see *why* a query was issued.

## Providers, and the credentials that do not exist here

| Provider | Needs | Status in this build |
| --- | --- | --- |
| **No search provider** (default) | nothing | selected by default; the run stops before any network call and says so |
| **Operator-supplied URLs** | nothing | fully working: the URLs are fetched, extracted and stored |
| **Wikipedia** (MediaWiki Action API) | no key | implemented against the documented public API; an encyclopedia, labelled as a secondary source |
| **Brave Search** | a Brave API key | **unavailable**: listed with its requirement, refuses to run |

No key is invented, none is stored in the renderer, and an architecture guard
fails the build if `API_KEY`, `apiKey` or `process.env` appears anywhere in the
retrieval layer. A search provider's key belongs on the relay (server side), and
this build has no relay route for search — so the honest state of that provider is
"not configured", shown in the panel, not a button that pretends.

## What may be fetched

`checkResearchUrl` is the single decision point, and it is consulted twice: before
the transfer (`fetchSource`) and again when a stored citation is judged
(`chunkSource`), so a citation that no longer satisfies the policy is reported as
failing rather than counted as support.

Refusals, all with a code and a reason:

- **scheme** — only `http` and `https`; `file:`, `data:`, `javascript:`, `ftp:`,
  `chrome:` are refused.
- **credentials** — a URL with `user:pass@` is refused, because those credentials
  would be sent.
- **insecure** — plain `http` is refused unless the operator allows plaintext for
  the run.
- **private-address** — loopback (127/8, `::1`), private (10/8, 172.16/12,
  192.168/16), link-local (169.254/16, fe80::/10), CGNAT (100.64/10), reserved and
  documentation ranges, multicast, unspecified, IPv4-mapped private IPv6,
  `localhost`/`*.local`/`*.internal`/`*.home.arpa`, single-label hostnames, and
  known metadata hostnames. These are refused even when the host allowlist names
  them.
- **host-not-approved** — nothing is fetched from a host the operator has not
  approved for the run. The allowlist is built from the URLs the operator typed, or
  from the hosts a provider returned, plus the provider's own API host.

Transfer limits, all enforced:

- **redirects: zero.** A renderer-side `fetch` cannot read the `Location` header of
  a cross-origin redirect (`redirect: "manual"` yields an opaque response), so
  following one would hand the connection to a URL this app never checked. A
  redirect is reported as a refusal with the original URL; the operator can add the
  destination explicitly if it is approved. An architecture guard forbids
  `redirect: "follow"` anywhere in the app.
- **content type**: `text/html`, `application/xhtml+xml`, `text/plain`,
  `text/markdown`, `application/xml`, `text/xml`. Anything else (a PDF, an image,
  an installer) is refused rather than reinterpreted.
- **size**: 2 000 000 bytes, checked against `content-length` and enforced while
  streaming. A response over the cap is *refused*, not truncated: keeping the first
  megabytes of a document and then claiming to describe it would be a lie of
  omission. (Extraction has its own 60 000-character cap, which is reported as
  truncation because the *page* was fetched and read in full.)
- **time**: 10 000 ms per request, merged with the run's cancellation signal, and
  the reason is recorded on the link so a slow host is never reported as an
  operator cancellation (or the reverse).
- **cancellation**: a cancelled run records `cancelled` for the URL it stopped at
  and fetches nothing further.

### The honest limitation

The browser resolves hostnames, so a *public* name that resolves to a private
address cannot be detected from the renderer. That is precisely why an allowlist is
required: the address rules are defence in depth, and the allowlist is the control.
CORS is also the browser's to enforce — a host that does not send permissive
headers shows up as a network failure, reported as such.

## Extraction: a page is data, never code

- The document is parsed with `DOMParser`, which produces an **inert** tree:
  scripts never run, images and frames are never loaded, and the tree is never
  inserted into the live document. Guards forbid `innerHTML`,
  `dangerouslySetInnerHTML`, `document.write` and `createContextualFragment` in the
  retrieval layer and its panel.
- `script`, `style`, `noscript`, `iframe`, `object`, `embed`, `svg`, `canvas`,
  `template`, `form`, `link` and `meta` are removed before text is read — and
  counted, so the panel can say how much was removed.
- Outbound links are counted and never followed: this build does not crawl. There
  is no fetch of a page's sub-resources, no sitemap walking, no link expansion.
- The extracted text is passed through `neutraliseActionBlocks`, the same routine
  the tool layer uses, so a `<blackletter-action>` block in a page cannot smuggle a
  proposal back into the app through retrieved content.
- Metadata is read before anything is stripped, because a page's claims about
  itself (byline, publisher, date, canonical URL) are *data about the source*, and
  the panel labels them as such. A date that cannot be parsed is `null`, never
  guessed.

## Provenance on every source

`url`, `canonicalUrl`, `title`, `publisher`, `author`, `publishedAt` (or `null`),
`retrievedAt`, `method`, `contentType`, `contentHash` (extracted text),
`rawHash` (raw bytes, so a changed page is detectable), `textTruncated`,
`sanitisedElements`, `linksNotFollowed`, and a content-addressed id derived from
the canonical URL — so the same page keeps the same identity across runs and
citations stay resolvable.

**Kind labels are a heuristic with a stated basis.** `likely-primary`,
`secondary`, `commentary` or `unknown` is decided by domain and path rules
(`.gov`/`.edu`/publisher hosts, news organisations, self-published platforms), and
the reason travels with the label. Nothing treats `likely-primary` as proof of
anything; it adjusts a ranking prior and is shown as a label.

### Duplicates and syndication

Three rules, applied together: the same canonical URL, the same extracted-text
digest, or ≥ 85 % shared five-word wording. Members of a group are listed as
`duplicates` of each other and one is the representative. Claim support counts
**independent** representatives, so a claim carried by five copies of one wire
story is reported as one source with five URLs, and the panel says so on the claim
itself.

## Claims, conflicts, and what "verified" means here

Claim support is decided by `attributeClaims` from `src/pipeline/grounding.ts` —
the same function the report uses, and the only implementation in the app (a guard
enforces that). What the retrieval layer adds is provenance: which sources the
supporting passages came from, and how many of them are independent.

- A claim that states a number is only supported by a passage containing that
  number (the grounding policy), which is what stops "900 megawatts" from being
  "supported" by "90 megawatts".
- A passage that does not reproduce from the stored text, or whose URL no longer
  passes the fetch policy, is **not counted**, and the claim says why.
- `supported` / `partial` / `unsupported` are shown with the overlap value and the
  supporting links, never as a bare word.

Conflicts are reported and never resolved:

- **contradiction** — two claims covering the same terms where one is negated, or
  where the stated figures differ;
- **date-mismatch** — a cited source published outside the period the question
  declared;
- **stale-source** — a cited source older than five years relative to the run.

Claim locators are `https://host/path#chars=start-end` into the stored text, and
`passageTextAt` re-derives the passage from the record, so a reader can check a
citation without trusting the extractor. `resolves` means "still passes the
destination policy" — it is **not** a liveness check, and the panel does not
present it as one.

## Storage

Runs are stored in `src/research/web/log.ts`, separately from the workspace store
(the same pattern as the tool audit trail): frozen records, newest first, capped at
**10 per workspace** and **30 in total**, persisted through the shared key-value
store, and reloaded on demand. What falls off the cap is counted and shown. A run
records the `approvedHosts` it used, so a later re-binding judges the stored
sources under the same policy.

## Where it appears

Developer Mode → **Web research**: provider selection with requirements, the
question form, a URL box for the manual provider, a synthesis box pre-filled from
the active tab's last answer, the run button with cancellation, and then the run:
summary, plan, retrieved sources (clickable), refusals with reasons, claims with
their status and supporting links, and conflicts. Nothing on the panel runs
automatically, and nothing is pre-populated with sample data — a guard requires
that the panel is rendered only from Developer Mode.

## What is not verified

- **No live provider call was made while building this.** There is no network
  access from the build environment and no search API key, so every test replaces
  `fetch` with a router and asserts both the success and the refusal paths. The
  Wikipedia provider is implemented against its documented API but has not been
  exercised against the live endpoint here.
- **The Brave provider is deliberately inert** in this build: the key belongs on a
  relay that does not exist yet. Selecting it performs no search.
- **No crawl, no PDFs, no Office documents from URLs.** Only the six text content
  types above are extracted. A PDF served from a URL is refused, not misread.
- **URL liveness is not checked.** A citation's URL is verified against the policy
  and its passage against the stored bytes; whether the page is still online today
  is not claimed.
- **Differentiation thresholds are policy, not measurement**: the 85 % overlap for
  syndication and the ≤ 4-query plan are stated choices, chosen so a run is bounded
  and reproducible.
- **Only the deterministic planner exists.** No model writes a search plan, and the
  synthesis that gets bound is written by the operator or by the pipeline's own
  answer — the panel does not generate prose.
